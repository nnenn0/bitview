# 言語

テンプレートの書き方と、読み込み時に行う型の検査をまとめます。ホストのRustから使う方法は[ホストからの使い方](host.md)を参照してください。

## 構文

ソースファイルの拡張子は `.bv` です。Clojureに似たS式で書きます。

| 書き方 | 意味 |
| --- | --- |
| `(defn name [a String b Entry] expr)` | 関数の定義。引数ごとに名前の後に型を書く。本体は1つの式 |
| `(defn- name [a String] expr)` | 定義したファイルの中でだけ呼べる関数の定義 |
| `(f x y)` | 関数の呼び出し。先頭に書けるのは関数の名前だけ |
| `a.b.c` | 引数 `a` のフィールドの参照。`.` の前後に空白を入れない |
| `"text"` | 文字列 |
| `[x y z]` | リスト |
| `{:href "/" :class "x"}` | レコード。キーは `:` に続く名前 |
| `(if c x y)` | `c` が真なら `x`、偽なら `y` |

- 値はString、Bool、List、Record、Htmlの5種類です。
- 名前は小文字と数字を `-` でつないだものです（`entry-list`）。CSSのクラス名やファイル名と同じ綴りにできます。`defn`・`defn-`・`if` は名前に使えません。
- 大文字で始まる語は型の名前で、引数の後にだけ書けます（[型](#型)）。
- `;` から行末まではコメントです。
- フィールドを読めるのは引数の名前だけで、`(f x).b` とは書けません。関数が返したレコードは、それを受け取る関数の引数として読みます。

## 関数

`defn` で定義した関数は、すべてのファイルとホストから名前で呼べるので、名前はファイルをまたいで1つずつしか定義できません。

`defn-` で定義した関数は、そのファイルの中からしか呼べず、ホストも入口として呼べません。そのため、別々のファイルが同じ名前の `defn-` の関数を持てます。ファイルの中では、`defn-` の関数が、ほかのファイルにある同じ名前の `defn` の関数を隠すので、ほかのファイルに関数が増えても、そのファイルの呼び出し先は変わりません。

1つのファイルの中で同じ名前を2回定義するとエラーになります。引数は同じ名前の関数を隠すので、`(defn heading [title String] (h1 title))` と書けます。隠された名前を呼ぶとエラーになります。

呼び出し先はすべて読み込み時に決まります。関数が自分自身を直接または間接に呼ぶ再帰は、読み込み時にエラーになります。

## 標準ライブラリ

- HTML要素の関数: `(p ...)`、`(a {:href "/"} "top")` のように呼びます。最初の引数がレコードなら属性です。空要素（`br`、`img` など）は子の引数を取りません。
- `concat`: 文字列を連結します。
- `(map list 関数名)`: リストの各要素に関数を適用します。2つ目の引数には、定義した関数の名前だけを書けます。

## 型

関数の引数には必ず型を書きます。

| 型 | 書き方 |
| --- | --- |
| 文字列、真偽値 | `String`、`Bool` |
| Html | `Flow`（`body` の中身）、`Phrasing`（文中に置けるもの）、`Metadata`（`head` の中身） |
| リスト | `[String]` |
| レコード | `{:title String :draft Bool}` |
| ホストが名前を付けた型 | `Entry` など（[ホストが名前を付ける型](host.md#ホストが名前を付ける型)） |

```clojure
(defn draft-badge [entry {:draft Bool}]
  (if entry.draft (span {:class "draft-badge"} "draft") []))
```

- レコードの型は、関数が読むフィールドを並べたものです。それ以上のフィールドを持つレコードも渡せるので、記事と一覧の項目のように、別々の型のレコードを同じ関数に渡せます。
- 関数の中から見えるのは、型に書いたフィールドだけです。書いていないフィールドを読むとエラーになるので、型を見れば、関数が何を読むかがわかります。
- Htmlの型は `Flow`・`Phrasing`・`Metadata` の3つです。`li` だけを並べたHtmlのように、これらで表せないHtmlを受け取る関数は書けません。

## 型の検査

読み込むときに、すべての関数を、引数の型だけを手がかりに1つずつ検査します。関数の本体は、呼び出し元から何が渡されるかに関係なく型だけで検査が決まるので、どこからも呼ばれない関数も検査します。検査は `if` の両側と `map` の中にも及ぶので、特定のデータのときにしか通らない分岐の誤りも、描画の前に見つかります。

誤りは、誤りのある関数の中の位置で報告します。

```text
views/components/draft-badge.bv:2:54: unknown field "titel" (fields: title, draft)
  in draft-badge
```

見つかる誤りは次のとおりです。

- 存在しないフィールドの参照
- 型の合わない値。本体は渡される値ではなく書いた型で検査するので、`[x Flow]` の `x` はブロックを含むかもしれないHtmlとして扱い、`(p x)` は文字列しか渡されなくてもエラーになります。文中に置くHtmlなら `Phrasing` と書きます。
- 引数の型に合わない呼び出し。呼び出しの位置でエラーになります（`entry has no field "draft", which its type lists`）。
- 要素に書けない属性（`herf` のような綴りの誤りを含む）
- HTMLで置けない入れ子（[値とHtml](#値とhtml)）

URLのスキームのように、値そのものに依存する誤りは描画時に見つかります。

## 値とHtml

- Htmlは、HTMLの断片、つまりノードの並びです。文字列は1つのテキストノードの断片として、断片のリストはそれらを順に並べた1つの断片として、Htmlの代わりに使えます。`[]` は空の断片でもあるので、何も出さない側は `[]` と書きます。
- `if` の型とリストの要素の型は、両側を合わせられる最小の型になります。`(if c (span "x") [])` はHtml、`(if c [(h1 "x") (p "y")] [])` はHtmlのリストになり、どちらも断片として要素の子に置けます。
- Htmlの型は、置ける場所の分類（文中に置ける要素、ブロック、`li`、表の行、`head` の中身など）を持ちます。要素ごとに中に置ける分類が決まっているので、`(p (div ...))`・`(ul (p ...))`・`(head (p ...))`・`a` の中の `a` は、ブラウザーが黙って組み替える前に、型の検査でエラーになります。

  ```text
  views/pages/entry.bv:2:4: <p> cannot contain block elements such as <p> and <div>; it takes text, phrasing elements such as <span> and <a>
    in entry
  ```

- `a` は中身と同じ分類になるので、ブロックを包んだ `a` はブロックが置ける場所にだけ置けます。

## HTMLの安全性

- 文字列は、HTMLに書き出すときに必ずエスケープします。文字列をHTMLに変える手段（`raw`、`safe`）はありません。
- 書ける属性は、全要素に共通の属性（`id`・`class`・`title`・`lang` など）、要素ごとに決めた属性（`a` の `href`・`target`・`rel` など）、`data-*`、`aria-*` だけです。`on*` 属性と `style` 属性は書けません。
- `script` 要素はありません。`<style>` とJSONのデータは、ホストが作って渡します（[ホストが作るHtml](host.md#ホストが作るhtml)）。
- `href`・`src`・`cite` と、複数のURLを並べる `srcset`・`imagesrcset`・`ping` は、どのURLもスキームが `http`・`https`・`mailto` か相対URLでなければ、描画時にエラーにします。
